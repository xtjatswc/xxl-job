# xxl-job 信创改造排障指南（金仓数据库 KingbaseES）

> 记录改造过程中遇到的所有编译/依赖/运行错误及其解决方案，供后续部署参考。

## 一、环境准备

xxl-job-admin 默认使用 MySQL，信创改造目标为金仓数据库 KingbaseES 8.x。


## 二、依赖问题排查

### 问题 1：`Could not resolve dependency - com.kingbase8:kingbase8:jar:8.6.0 was not found`

#### 现象
Maven 编译报错，提示找不到 `com.kingbase8:kingbase8:8.6.0`。

#### 根因
`kingbase8` 是人大金仓商业发行版，**不在 Maven 中央仓库**，也不在我们公司的内部 Maven 私服（hse-releases）里。

#### 解决步骤

**第一步：找到 Kingbase 驱动的 JAR 文件**

在已安装 Kingbase 开发环境的机器上搜索：
```bash
# 常见路径
find /c -name "kingbase8-*.jar" 2>/dev/null
# 或通过 IDE 查看：
# IntelliJ IDEA → File → Project Structure → Libraries → 搜索 kingbase8
```

实际找到的路径示例：
```
C:/Program Files/kstudio/configuration/org.eclipse.osgi/13/0/.cp/lib/kingbase8-8.6.0.jar
```

**第二步：安装到本地 Maven 仓库**
```bash
mvn install:install-file \
  -Dfile="C:/Program Files/kstudio/configuration/org.eclipse.osgi/13/0/.cp/lib/kingbase8-8.6.0.jar" \
  -DgroupId=com.kingbase8 \
  -DartifactId=kingbase8 \
  -Dversion=8.6.0 \
  -Dpackaging=jar \
  -DgeneratePom=true
```

**第三步：验证安装成功**
```bash
ls ~/.m2/repository/com/kingbase8/kingbase8/8.6.0/
# 应看到：kingbase8-8.6.0.jar 和 kingbase8-8.6.0.pom
```

#### 其他机器的部署注意
- 新机器上没有 Kingbase 开发工具时，需要先从单位内网下载 Kingbase 安装包获取 JAR 文件
- 或者将 JAR 文件放入公司内部的 Maven 私服，配置 settings.xml 的 mirror

### 问题 2：Maven `.lastUpdated` 缓存导致重复失败

#### 现象
清理后重新编译偶尔仍报找不到依赖，即使 JAR 已经存在于本地仓库。

#### 根因
Maven 在每次尝试下载依赖后，会在对应版本目录下生成 `.lastUpdated` 文件。
如果之前下载失败，Maven 会读取这个文件并缓存"此依赖不存在"的结果，
直到缓存过期才会重试。

#### 解决步骤
```bash
# 清理所有 stale 缓存文件
find ~/.m2/repository -name "*.lastUpdated" -delete

# 强制更新依赖（如果还需要从远程拉取）
mvn dependency:resolve -U
```

---

### 问题 3：IDEA 编译报 `程序包 org.apache.ibatis.annotations 不存在`

#### 现象
Maven CLI 编译通过，但 IDEA 显示 MyBatis 注解类找不到。

#### 根因
IDEA 的 Maven 集成和命令行 Maven 可能使用不同的仓库路径或索引策略。
`.lastUpdated` 缓存文件会影响 IDEA 的判断。

#### 解决步骤
1. 执行上面的 `.lastUpdated` 清理命令
2. 在 IDEA 中：`File → Invalidate Caches → Invalidate and Restart`
3. 右键项目 pom.xml → `Maven → Reload Project`
4. 等待索引重建完成后再编译

### 问题 4：编译报错 `Could not resolve dependencies - xxl-job-core:3.5.1-SNAPSHOT`

#### 现象
编译 xxl-job-admin 时报找不到 xxl-job-core 依赖。

#### 根因
SNAPSHOT 版本的模块需要先在本地安装，不能直接从远程仓库获取。

#### 解决步骤
```bash
# 先安装 xxl-job-core 到本地仓库
cd xxl-job
mvn clean install -pl xxl-job-core -am -DskipTests -Dgpg.skip=true

# 再编译 admin
mvn clean package -pl xxl-job-admin -am -DskipTests -Dgpg.skip=true
```

注意：加 `-Dgpg.skip=true` 跳过 GPG 签名（本地开发环境通常没有 GPG key）。

## 三、运行时错误排查

### 问题 5：`Invalid bound statement (not found): XxlJobLockMapper.scheduleLock`

#### 现象
应用启动后运行报错，提示找不到 `scheduleLock` 方法对应的 SQL 语句。

#### 根因
创建的 `mapper/kingbase/XxlJobLockMapper.xml` 中写的方法名与 Java 接口不匹配。
Java 接口只有 `scheduleLock()` 方法，但 XML 里写了 `getLock`、`addLock`、`delLock`。

#### 正确写法
```xml
<!-- mapper/kingbase/XxlJobLockMapper.xml -->
<mapper namespace="com.xxl.job.admin.business.mapper.XxlJobLockMapper">
    <select id="scheduleLock" resultType="java.lang.String">
        SELECT lock_name FROM xxl_job_lock
        WHERE lock_name = 'schedule_lock'
        FOR UPDATE
    </select>
</mapper>
```

> `FOR UPDATE` 是标准 SQL，KingbaseES 完全支持，无需特殊处理。

### 问题 6：`Error setting non null for parameter #2, column index out of range`

#### 现象
`XxlJobRegistryMapper.findDead` 运行时报错：
```
com.kingbase8.util.KSQLException: The _column _index is out of range: 2, number of _columns: 1
```

#### 根因
SQL 写法 `INTERVAL '#{timeout}' SECOND` 中，单引号将 `#{timeout}` 当成字符串字面量，
Kingbase JDBC 驱动无法正确解析参数占位符，导致参数绑定错位。

#### 错误写法
```xml
WHERE t.update_time < #{nowTime} - INTERVAL '#{timeout}' SECOND
```

#### 修复过程（多次尝试）

| 尝试 | 写法 | 结果 |
|-----|------|------|
| 1 | `INTERVAL '#{timeout}' SECOND` | 参数绑定错位 |
| 2 | `${timeout} * INTERVAL '1' SECOND` | 类型不匹配（见问题 7） |
| 3 | `INTERVAL '${timeout} SECOND'` | 仍报类型不匹配 |
| 4 ✅ | **日期计算移到 Java 层** | **解决** |

#### 最终方案
**不在 SQL 中做日期运算，在 Java 层预先计算 deadline：**

```java
// JobRegistryHelper.java / JobGroupController.java
Timestamp deadline = Timestamp.from(Instant.now().minusSeconds(Const.DEAD_TIMEOUT));
mapper.findDead(deadline);
mapper.findAll(deadline);
```

```xml
<!-- mapper/kingbase/XxlJobRegistryMapper.xml -->
<select id="findDead" resultType="java.lang.Integer">
    SELECT t.id FROM xxl_job_registry AS t
    WHERE t.update_time < #{deadline}
</select>

<select id="findAll" resultMap="XxlJobRegistry">
    SELECT ... FROM xxl_job_registry AS t
    WHERE t.update_time > #{deadline}
</select>
```

同时修改 Mapper 接口签名：
```java
// 从
List<Integer> findDead(@Param("timeout") int timeout, @Param("nowTime") Date nowTime);
// 改为
List<Integer> findDead(@Param("deadline") Date deadline);
```

### 问题 7：`operator does not exist: timestamp without time zone < pg_catalog.interval`

#### 现象
使用问题 6 的第二种尝试方案后报错：
```
ERROR: operator does not exist: timestamp without time zone < dsinterval
```

#### 根因
`90 * INTERVAL '1' SECOND` 在 Kingbase 中被解析为 `dsinterval`（持续时间间隔），
而 `timestamp - dsinterval` 运算符在此版本 Kingbase 中未定义。

#### 结论
KingbaseES 对 PostgreSQL 的 interval 运算支持不完善，**不要在 SQL 中做日期减法**。
统一采用"Java 层计算 deadline，SQL 只做比较"的方案。

---

### 问题 8：缺少 `registryDelete` 和 `removeByRegistryGroupAndKey` 方法

#### 现象
运行时 NPE 或 NoSuchMethodError。

#### 根因
创建 Kingbase Mapper XML 时遗漏了这两个 `<delete>` 语句。

#### 修复
在 `mapper/kingbase/XxlJobRegistryMapper.xml` 中补充：
```xml
<delete id="registryDelete">
    DELETE FROM xxl_job_registry
    WHERE registry_group = #{registryGroup}
      AND registry_key = #{registryKey}
      AND registry_value = #{registryValue}
</delete>

<delete id="removeByRegistryGroupAndKey">
    DELETE FROM xxl_job_registry
    WHERE registry_group = #{registryGroup}
      AND registry_key = #{registryKey}
</delete>
```

## 四、KingbaseES 语法对照速查表

| MySQL 语法 | KingbaseES 语法 | 说明 |
|-----------|----------------|------|
| `LIMIT offset, pagesize` | `LIMIT pagesize OFFSET offset` | 标准 SQL 分页 |
| `CONCAT('%', var, '%')` | `'%' \|\| var \|\| '%'` | 字符串拼接 |
| `IFNULL(x, y)` | `COALESCE(x, y)` | 空值处理 |
| `DATE_ADD(now, INTERVAL n SECOND)` | **Java 层计算** | SQL 不做日期运算 |
| `ON DUPLICATE KEY UPDATE` | `ON CONFLICT (col) DO UPDATE SET ...` | 插入更新 |
| `AUTO_INCREMENT` | `SERIAL` / `BIGSERIAL` | 自增序列 |
| `ENGINE=InnoDB CHARSET=utf8mb4` | 移除 | Kingbase 默认 |
| `USING BTREE` | 移除 | 默认 B-tree |
| `MEDIUMTEXT` | `TEXT` | 文本类型 |
| `TINYINT` | `SMALLINT` | 整数类型 |
| `DATETIME` | `TIMESTAMP` | 时间类型 |
| 数据库创建 | `CREATE DATABASE ... ENCODING 'UTF8'` | 字符集 |
